# Тести

Сім наборів. Логіка пошуку перевіряється в Node, поведінка інтерфейсу — у headless-Chromium
через puppeteer. Порядок у таблиці — той, у якому їх запускає `run.sh`.

| Файл | Що перевіряє | Потрібен браузер |
|---|---|---|
| `unit.js` | пошук і реперторизація прямо через `repertory.js` і `data/` | ні |
| `basic.js` | дві мови, перемикач UA/RU, пошук, підказки, сторінки препаратів і статей, тема, мобільна ширина | так |
| `features.js` | список модальностей і причин, ваги ×2/×3, елімінативні (!) і виключні (−) рубрики, сортування, порівняння препаратів, підстави з речень, перемикач «Статті», перенесення рубрик між мовами | так |
| `cases.js` | збережені випадки (зберегти, відновити з меню, оновити, видалити) і друк: схована шапка, блок `.print-only`, усі рядки без пагінації, сторінка препарату | так |
| `feedback.js` | «Повідомити про помилку» (адреса сторінки, мова, збірка, виділений текст), розмір шрифту, клавіша «/», вкладені підказки | так |
| `modal2.js` | фаза 2 модальностей: два ступені в рубриці, підстави видобутої модальності (речення + розділ), кількість у списку рубрик = лише секційні | так |
| `pwa.js` | реєстрація service worker, маніфест та іконки, робота без мережі (відвідане і збережене), «Зберегти довідник для офлайну» / «Видалити», пошук офлайн | так |

`modal2.js` бере препарат і очікувані числа зі зібраного `data/ru/`, а не з констант, тож переживає
уточнення регексів.

Кожен набір друкує рядки `OK …` / `FAIL …` і повертає ненульовий код виходу, якщо є провал.

`pwa.js` вимикає мережу і сторінці, і воркерові (це окрема ціль DevTools) і перед кожною
офлайн-перевіркою доводить, що мережі справді немає: закешована адреса має віддатись, а
незакешована — провалитись. Інакше «працює офлайн» проходило б на живій мережі.

## Прогін

```
tools/uitest/run.sh            # усі набори на власному сервері (порт 8765), ≈40 с
tools/uitest/run.sh 9000       # інший порт
node tools/uitest/unit.js      # лише перевірки пошуку, секунди, без сервера і браузера
```

`run.sh` піднімає `python3 -m http.server ПОРТ --bind 127.0.0.1` з кореня репозиторію (усі шляхи
в сайті відносні, тож корінь працює як адреса сайту), чекає готовності й послідовно запускає
**всі** `*.js` цієї теки: спершу `unit`, `basic`, `features`, далі решту за абеткою (`cases`,
`feedback`, `modal2`, `pwa`). Наприкінці друкує підсумок і зупиняє сервер. Новий набір досить покласти
поряд — окремо його прописувати не треба.

Окремий набір проти вже піднятого сервера або проти живого сайту — без `run.sh`:

```
BASE=https://ix21027.github.io/homeo-repertory/ node tools/uitest/basic.js
BASE=http://127.0.0.1:8765/ node tools/uitest/pwa.js
```

`pwa.js` вимагає, щоб `BASE` був на `localhost`/`127.0.0.1` або HTTPS: service worker більше
ніде не працює. `run.sh` саме так і піднімає сервер, а от проти `file://` цей набір не піде.

## Змінні середовища

| Змінна | Типово | Навіщо |
|---|---|---|
| `BASE` | `http://127.0.0.1:8765/homeo-repertory/` | адреса сайту; має закінчуватись на `/` |
| `CHROME` | `/home/ubuntu/.cache/ms-playwright/chromium-1228/chrome-linux/chrome` | шлях до Chromium |
| `SHOTS` | `tools/uitest/shots/` | тека знімків екрана (`basic/`, `features/`, `cases/`, `feedback/`, `pwa/`); у `.gitignore` |
| `PUPPETEER` | `/home/ubuntu/node_modules/puppeteer` | шлях до puppeteer (він поза репозиторієм, залежностей у проєкті немає) |

`CHROME` вказує на Chromium від Playwright, бо власний Chrome puppeteer на цій arm64-машині не
запускається. На іншій машині досить поставити puppeteer (`npm i puppeteer`) і задати `PUPPETEER`
та `CHROME` під себе.

## CI

`.github/workflows/build.yml` на кожен push і pull request у `main` робить `node tools/build.mjs`
і `node tools/uitest/unit.js`. Браузерні набори в CI не ганяємо — puppeteer там нестабільний, їх
проганяють локально перед комітом помітних змін в інтерфейсі. Збірка перезаписує `data/`, тому
diff `data/` у CI не перевіряється (у каталозі є дата збірки).
